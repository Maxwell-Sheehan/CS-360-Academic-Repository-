# CS-360-Academic-Repository-

Briefly summarize the requirements and goals of the app you developed. What user needs was this app designed to address?

The main goal of the app was to create a fitnesse app that allowed users to enter their weight everyday and have it tracked within their account everyday when they logged in. Users would recieve SMS notificiations when they hit certain weight goal thresholds. The app was designing and focused on enabling users to live a more active lifestyle, and be enabled in being a more fit version of themselves. 

What screens and features were necessary to support user needs and produce a user-centered UI for the app? How did your UI designs keep users in mind? Why were your designs successful?

The most important screen was the UI element that allowed users the feature to add their weight and have it stored day to day. The UI keeps users in mind by exporting that data into an in-app line graph that shows a clear trend of their data and progression. I think this design was successful by allowing users to see more then just a number, but a sense of progress seeing the graph trend downwards, possibly even giving them a second wind when they begin to feel burnt out from the process. 

How did you approach the process of coding your app? What techniques or strategies did you use? How could those techniques or strategies be applied in the future?

Android studios is and IDE I've never used before, so my coding was very reserved and had a lot of trial and error as I researched and got more familiar with the process. With all design I believe things should be as modular as possible, seperating code into as many classes and individual functions as possible to protect as much of the software as possible. I think this kind of OOP approach is something i've utilizied in the past, and plan to continue to use as it makes all stages of devlopment much easier and safer.

How did you test to ensure your code was functional? Why is this process important, and what did it reveal?

One great thing about andriod stuido was the preview window of your code, this made testing much quicker for basic logic errors as it was reflected in the visual preview. Otherwise for testing simply running the code and testing values within their own fields allowed for basic trial and error which when iterated over and over reveals many flaws and room for improvenment.
